# Governance

ClimaDC uses maintainer review with evidence-first release gates. Maintainers decide scope, API and
artifact compatibility, security response, and releases in the open through issues and pull
requests. Decisions affecting causal semantics, evidence claims, objectives, or artifact contracts
require an ADR and tests.

Contributors may propose changes through a focused pull request. Approval means the change matches
the documented scope and verification gates; it does not endorse downstream operational use.
Quantitative claims require a registry entry and reproducible artifact. Security reports follow
[`SECURITY.md`](SECURITY.md) rather than public issue discussion.

One approving maintainer is sufficient while the project has one listed maintainer. A future
maintainer is added only after sustained reviewed contributions and explicit consent. Project
membership, affiliations, ORCIDs, and institutional endorsements are never inferred.
