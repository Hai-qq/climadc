# ClimaDC v0.3 baseline audit

Status: pre-change audit
Audited branch: `codex/v0.3-evidence-hardening`
Pinned baseline: `dcce5f3eecb958586800d4d65d4034bc3568e1f9` (`v0.2.0-alpha.1`)
Audit environment: Windows, CPython 3.11.9, 2026-08-21

This record describes the repository before the v0.3 evidence-hardening changes. It separates
implemented behavior from claims that the current artifacts cannot independently prove.

## Product boundary

The implemented product is an offline forecasting benchmark and engineering replay framework. The
causal boundary is encoded by `ClimateForecastFrame`, `GridSignalFrame`,
`FlexibleWorkloadFrame`, `LeakageGuard`, and the decision-time preparation performed by
`prepare_replay_inputs()` in `src/climadc/replay/inputs.py`. The public positioning in `README.md`
and `docs/design/v0.2-engineering-replay.md` excludes online actuation, Kubernetes scheduling,
reinforcement learning, a dashboard, a digital twin, and a model zoo.

The v0.3 target remains an offline framework for climate-aware data-center decisions with causal
time semantics and an auditable evidence chain. None of the changes planned below introduce an
online control path.

## Architecture and module boundaries

| Boundary | Current implementation | Evidence and responsibility |
|---|---|---|
| Canonical data | `src/climadc/contracts/frames.py` | Exact-column wrappers validate units, finite values, keys, quality labels, and causal timestamp ordering. `ClimateForecastFrame` requires `issue_time <= available_at <= valid_time`; realized grid rows require `valid_time <= available_at`. |
| Local/external adapters | `src/climadc/adapters/` | Local CSV/Parquet readers and read-only provider converters. `OpenMeteoHistoryAdapter.fetch()` and `NESOCarbonIntensityAdapter.fetch()` currently return normalized objects, but discard the raw HTTP byte stream. |
| General benchmark | `src/climadc/benchmark.py`, `src/climadc/backtesting/`, `src/climadc/forecasting/`, `src/climadc/calibration/`, `src/climadc/evaluation/` | Leakage-aware temporal splits, lightweight forecasting, calibration, evaluation, and optional shadow comparison. |
| Engineering replay | `src/climadc/replay/inputs.py`, `engine.py`, `rolling.py`, `study.py` | `ReplayStudyRunner.run()` verifies the source manifest, loads canonical inputs, runs single-window or rolling replay, and freezes config/input hashes. `ReplayEngine.run()` solves ASAP, peak, price, carbon, joint, optional risk-aware, and Oracle policies with SciPy HiGHS. |
| Suite aggregation | `src/climadc/replay/suite.py` | `ReplaySuiteRunner.run()` checks coarse scenario comparability, runs each study, aggregates signed deltas, and computes a three-objective Pareto frontier. Current class/field names call every suite “robustness” even when scenarios reuse one day and workload. |
| Artifact publication | `src/climadc/reporting/artifacts.py`, `src/climadc/replay/artifacts.py`, `src/climadc/replay/suite_artifacts.py` | Writers stage into a temporary directory, validate against the still-live result object, atomically rename, then update a constrained `latest` pointer. There is no independent post-publication verifier. |
| Human reports | `src/climadc/reporting/html.py`, `src/climadc/replay/html.py`, `src/climadc/replay/suite_html.py` | Static self-contained HTML. Replay publication compares generated HTML byte-for-byte with an in-memory render, which cannot be repeated from only the published directory. |
| CLI | `src/climadc/cli/app.py` | Typer entry point; catches only `ClimaDCError` at command boundaries. |
| Packaging/release | `pyproject.toml`, `scripts/validate_release.py`, `.github/workflows/release.yml` | Hatchling build, tag/package validation, artifact upload, and trusted PyPI publication after a GitHub Release. |

Public replay APIs are re-exported by `src/climadc/replay/__init__.py`; adapter and contract APIs are
re-exported by their respective package `__init__.py` files.

## Current CLI

The commands registered in `src/climadc/cli/app.py` are:

- `climadc init DIRECTORY`
- `climadc validate CONFIG_PATH`
- `climadc benchmark CONFIG_PATH`
- `climadc replay CONFIG_PATH [--output-dir ...]`
- `climadc replay-suite CONFIG_PATH [--output-dir ...]`
- `climadc report RUN_OR_POINTER`
- `climadc demo carbon-shift [--output-dir ...]`
- `climadc demo robustness-suite [--output-dir ...]`
- `climadc demo refresh-carbon-shift DESTINATION --decision-date YYYY-MM-DD`

There is no `verify-run` or `verify-suite`. `report` only resolves `latest` and checks that
`report.html` exists; it does not validate the artifact set.

## Current artifact contracts

### General benchmark run

`REQUIRED_ARTIFACTS` in `src/climadc/reporting/artifacts.py` requires exactly eight files:
`run.yaml`, `lineage.json`, `splits.parquet`, `predictions.parquet`, `metrics.json`,
`leakage-report.json`, `dataset-card.md`, and `report.html`. There is no explicit artifact-schema
version, environment record, or complete checksum file. Validation is coupled to `RunResult` in
`ArtifactWriter._validate()`.

### Replay run (legacy artifact schema v1)

`REPLAY_ARTIFACTS` in `src/climadc/replay/artifacts.py` requires exactly 12 files:
`assumptions.yaml`, `source-manifest.yaml`, `lineage.json`, four canonical-input Parquet files,
`schedules.parquet`, `profiles.parquet`, `solver-status.json`, `replay-metrics.json`, and
`report.html`.

The replay JSON/YAML payloads use local `schema_version: "1"`, but there is no directory-level
version contract. `ReplayArtifactWriter._validate()` checks file equality against the originating
`ReplayStudyResult`, validates the four published input hashes through `SourceManifest`, and
reconstructs selected metrics from profiles and schedules. It does not record or verify:

- every artifact hash;
- Python/platform/dependency/solver versions;
- Git commit and dirty state;
- the full solver option set;
- schedule release/deadline/max-power/capacity invariants independently of the result object;
- numeric consistency between JSON and parsed HTML independently of a re-render;
- protection against a post-publication extra file.

The generated baseline replay directory contained these 12 files and completed all six policies.
It had no `run-manifest.json`, `environment.json`, or `checksums.sha256`.

### Replay suite (legacy artifact schema v1)

`REPLAY_SUITE_ARTIFACTS` in `src/climadc/replay/suite_artifacts.py` requires seven files plus a
`scenarios/` directory: `suite.yaml`, `lineage.json`, `scenario-index.json`,
`scenario-metrics.parquet`, `robustness-metrics.json`, `pareto-frontier.json`, and `report.html`.
Each scenario contains a complete 12-file replay subrun and its own `latest` pointer. Validation is
again coupled to `ReplaySuiteResult`; there is no recursive independent verification command or
suite-wide checksum contract.

## Data source chain

The packaged Great Britain fixture is rooted at
`src/climadc/reference/fixtures/gb_london_24h/`:

1. `source-manifest.yaml` records provider URLs, retrieval time, licenses, attribution, timing
   basis, limitations, byte size, and SHA-256 for the four canonical CSV inputs.
2. `ReplayStudyRunner.run()` loads that manifest and calls `SourceManifest.validate_files()` before
   parsing any input.
3. Local readers convert the CSVs into canonical wrappers.
4. `ReplayArtifactWriter._published_source_manifest()` rewrites the source records to point at the
   published Parquet inputs and re-hashes those files.

The optional network refresh in `refresh_carbon_shift()` currently calls
`OpenMeteoHistoryAdapter.fetch()` and `NESOCarbonIntensityAdapter.fetch()`, writes only normalized
CSV files, and generates `source-manifest.yaml`. `_transport()` in both provider adapters decodes
JSON immediately. Consequently, the original bytes, response status/headers, parser version, and
raw-hash-to-canonical-hash transformation cannot be audited after refresh. Injected transports used
by offline tests also return Python mappings, not response bytes.

The packaged fixture itself is hash-bound and forced to LF by `.gitattributes`, but its source
manifest points to canonical derived files rather than immutable raw responses.

## Computation chain

For an engineering replay:

1. `ReplayStudyConfig.from_yaml()` enforces strict configuration fields and resolves local paths.
2. `SourceManifest.validate_files()` checks canonical input bytes and coverage.
3. Contract wrappers validate schema, finite values, units, quality, and causal time order.
4. `prepare_replay_inputs()` selects the legal decision-time forecasts and post-horizon settlement
   values, normalizes units, aligns the horizon, and determines eligible job slots.
5. `ReplayEngine._constraints()` constructs job-energy equalities plus IT-capacity and peak
   inequalities; `_solve_policy()` calls `scipy.optimize.linprog(method="highs")` and checks energy,
   capacity, and eligibility postconditions.
6. `_base_metrics()` settles facility/IT/cooling energy, national-average carbon, scenario energy
   cost, demand charge, peak, deadline status, shifted energy, and Oracle regret.
7. `ReplayStudyRunner` calculates forecast and optional marginal quantile diagnostics.
8. Artifact writers serialize the frozen result and run an in-memory pre-publication validation.

The current `joint` and `oracle` objectives in `ReplayEngine._objective()` add
`cost_weight * currency` to `carbon_weight * kgCO2e`. `ReplayConfig` and `ReplaySettings` expose
only those unscaled weights. Documentation admits that the result is a comparison score, but the
configuration is not versioned and there is no deprecation warning. Demand charge is multiplied by
`cost_weight` in the joint objective.

## Conclusion chain

The home page currently presents two quantitative families:

- a project-generated WeatherDC regression fixture with near-zero OLS error;
- the 24-hour London engineering replay and four-scenario suite.

The prose contains important limitations, but there is no machine-readable claim registry tying a
sentence to commit, config hash, input hashes, output artifact, and reproduction command. The OLS
table can be misread as an accuracy claim despite being generated from synthetic plumbing data.
The London fixture combines external national/weather signals with a synthetic workload and
declared tariff. It supports a mechanism demonstration only, not production savings, marginal
emissions, or same-site validation.

`replay-metrics.json` currently calls the national-average settlement field
`emissions_kgco2e`. The computation is location-based estimated emissions; it is not avoided
marginal emissions. Provider quality is retained as `estimated` in canonical inputs, but that
qualification is not present in the metric name.

The tariff generator `_tariff()` calls `_tariff_value(slot.hour)` on UTC slots. Therefore the
packaged August scenario is a declared UTC tariff scenario, not a `Europe/London` civil-time tariff.
No DST boundary tests exist for the tariff.

The packaged `suite.yaml` already states that its four scenarios reuse one date and workload and
are sensitivity analysis. However, code/artifact field names and report headings still say
`robustness`, including `robustness-metrics.json` and “EQUAL-WEIGHT ROBUSTNESS STUDY”.

## Baseline risks

1. **Self-validation coupling:** published runs cannot be verified without the originating Python
   result objects; post-publication tampering is not comprehensively detectable.
2. **Incomplete provenance:** no raw provider responses or raw-to-canonical transformation ledger.
3. **Unscaled objective:** cost and emissions are added without a dimensional conversion in the
   default joint objective.
4. **Claim ambiguity:** no evidence levels or claim registry; synthetic sanity results can be
   visually over-weighted.
5. **Metric semantics:** national-average estimated settlement is not explicit in the public
   emissions metric name.
6. **Suite semantics:** sensitivity is named robustness in APIs, artifacts, and reports.
7. **Tariff time basis:** the fixture uses UTC hour-of-day without an explicit versioned tariff
   contract or DST tests.
8. **Supply chain:** floating Action tags, no dependency/SBOM/security workflows, and a currently
   failing Twine metadata compatibility check.
9. **Environment gaps:** solver/dependency/Git state and random seeds are not recorded per run.
10. **Long-term contract ambiguity:** README statements such as “exactly 12 artifacts” expose an
    implementation count rather than a versioned artifact schema.
11. **Platform test portability:** POSIX-symlink emulation is unconditionally attempted on Windows
    hosts that may lack Developer Mode or elevated privilege.

## Planned change surface

The implementation is expected to touch only the following logical areas:

- new `src/climadc/evidence/` modules for checksums, environment, manifests, claim validation, and
  independent run/suite verification;
- replay/benchmark/suite artifact writers and CLI registration;
- replay objective configuration/model/solver code and narrowly related reports;
- provider refresh adapters and reference refresh orchestration for immutable raw capture;
- suite configuration/naming and declared tariff-time helpers;
- packaged v0.3 reference configuration and a generated compact golden summary;
- focused tests under `tests/evidence/`, `tests/replay/`, `tests/adapters/`, `tests/cli/`, and CI/docs
  contract tests;
- version, changelog, citation, README, English/Chinese docs, API/migration/evidence/governance
  documents, ADRs, and workflows directly affected by these contracts.

Internal `docs/superpowers/` material will be evaluated for decisions worth retaining as ADRs. Any
removal will be limited to superseded prompt/plan residue and will not change runtime behavior.

## Explicit non-goals

- no online controller or actuation API;
- no Kubernetes scheduler, reinforcement-learning framework, simulator/digital twin, dashboard,
  monitoring platform, or model repository;
- no modification of the packaged synthetic workload or signal values to improve deltas;
- no fabricated trace benchmark, percentage, citation, deployment, or user case;
- no claim of E2 trace-driven validation or E3 same-site operational validation;
- no PyPI publication, GitHub Release, push to `main`, or repository-setting mutation;
- no broad refactor of forecasting, calibration, adapters, or legacy shadow scheduling unrelated to
  the evidence contract.

## Baseline decision

Proceed with v0.3 evidence hardening while retaining read-only legacy verification for the current
replay artifact schema. The new default must validate only published bytes and reconstructed
metrics; optional solver re-resolution must remain a separate, explicitly requested check.
