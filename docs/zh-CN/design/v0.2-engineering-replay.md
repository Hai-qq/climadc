# ClimaDC v0.2 工程回放技术设计

> 这是历史设计记录。v0.3 的产物、目标函数、排放和套件术语以
> [ADR 0002](../../adr/0002-artifact-schema-v2.md)、
> [ADR 0003](../../adr/0003-versioned-objectives.md)和
> [ADR 0004](../../adr/0004-evidence-levels-and-suites.md)为准，并取代对应的 v0.2 表述。

状态：阶段 0 的语义契约/本地读取器、阶段 1 的单窗口回放内核、阶段 2 的英国参考案例/CLI/产物、阶段 3 的可选只读适配器、阶段 4 的滚动编排/上分位数策略、阶段 5 的事后边际风险诊断，以及阶段 6 的多场景套件编排均已实现。按 v0.3 术语，内置阶段 6 矩阵是敏感性分析，不是稳健性验证。本文明确区分这些能力与其工程限制。

## 1. 产品问题

ClimaDC v0.2 只回答一个有工程意义的问题：

> 给定天气、电网信号、站点遥测和有截止时间的批处理任务，预测感知调度在使用带明确数据质量的声明结算值回放后，会怎样改变数据中心总能耗、碳排、电费、峰值和服务质量？

交付物是离线、可审计的工程研究，不是在线控制器；没有经过回放测量的收益不得宣称为节能效果。

## 2. 为什么 v0.1 还不够

v0.1 已提供准确的时间语义、防泄漏检查、时间回测、预测校准、产物谱系和能量守恒的影子优化器。但现有优化器把通用预测值作为成本指标，因此冷却功率预测、电价和碳强度在接口层可能被混用，而它们的单位和工程作用完全不同。现有合成案例验证的是链路，不是运营价值。

v0.2 将这些信号分离，并使用带明确数据质量的声明结算值进行反事实结算。

## 3. 范围与非目标

### 范围内

- 单站点，可运行完整决策窗口，也可在每个决策点重算并只提交配置步长的滚动时域；
- 具有释放时间、截止时间、能量需求和功率上限的可抢占批任务；
- 天气预报与事后天气；
- 电网碳强度预测与事后估算；
- 用户提供的电价和可选需量费用假设；
- 显式、可校准的数据中心能耗模型；
- 基线、预测感知、上分位数压力场景和 Oracle 调度；
- 使用真实结果回放并生成可审计报告。

### v0.2 不做

- 向生产基础设施下发调度；
- 强化学习；
- 多站点任务迁移；
- 通用遥测采集器或气象模型；
- Web 控制台；
- 用合成或仿真输入宣称生产节能效果。

## 4. 工程模型

每个时间间隔 `t` 的站点功率关系为：

```text
facility_power[t] = it_power[t] + cooling_power(it_power[t], weather[t], parameters)
```

打包的参考实现使用有文档说明且单调的温度敏感 PUE 曲线，其参数、来源和适用边界都会进入运行产物。用户可通过协议接入已校准模型，而不必修改回放引擎。

当前调度器先把每个输入转换到声明的标准单位，再使用硬服务约束和加权分数：

```text
sum_t(
    interval_hours
    * facility_power_kw[t]
    * (cost_weight * energy_price_per_kwh[t]
       + carbon_weight * carbon_intensity_per_kwh[t])
)
+ cost_weight * demand_charge_per_kw * facility_peak_kw
```

两个权重都不为零时，结果是比较分数而不是货币金额；权重声明研究对不同量纲的取舍。成本和碳排即使同时进入目标函数，也必须分别报告。配置的需量费用使用电价币种和当前窗口峰值，因此只是场景假设，不是完整月度费率复原。每个已接收任务都必须完成，所以截止时间或容量冲突会明确报告为不可行，而不是藏在服务惩罚项中。

## 5. v0.2 标准输入

| 契约 | 必须表达的含义 | 关键约束 |
|---|---|---|
| `ClimateForecastFrame` | 决策时刻已知的天气预报 | 保留 `issue_time <= available_at <= valid_time` |
| `DCTelemetryFrame` | 实际站点、IT 与冷却遥测 | 单位和观测质量明确 |
| `GridSignalFrame` | 碳强度和电价的预测或事后值 | 区分预测与事后值，单位必须匹配信号 |
| `FlexibleWorkloadFrame` | 每行一个可延迟批任务 | 释放、可用、截止、能量和最大功率显式化 |
| `PredictionFrame` | 数据中心功率或冷却功率预测 | 预测目标不得再充当电价或碳信号 |

`GridSignalFrame` 初期只支持 `carbon_intensity` 和 `energy_price`。预测行必须有起报时间，并满足 `issue_time <= available_at <= valid_time`；事后行没有起报时间，并满足 `valid_time <= available_at`。碳强度采用 `gCO2e/kWh` 等排放/能量单位，电价采用 `GBP/kWh` 等受支持的 ISO 货币/能量单位。

`FlexibleWorkloadFrame` 初期只建模可抢占任务。每个任务必须具有正的能量和最大功率、非负优先级，并满足 `release_time <= available_at <= deadline`。在新调度器迁移完成前，v0.1 的旧 `WorkloadFrame` 继续保留。

准确列名和本地读取器示例见[工程输入指南](../concepts/engineering-inputs.md)。

## 6. 决策与回放顺序

调用方直接提供天气预报，内核内部不再训练预测模型。研究运行器既可发布一个决策点，也可在多个滚动决策点重复同一套因果流程。每个决策点依次执行：

1. 只冻结 `available_at` 不晚于决策点的输入；
2. 使用合法的天气和遥测历史预测站点功率；
3. 构造 ASAP 基线调度；
4. 在相同约束下求解仅削峰、仅电价、仅碳排和联合目标方案；配置后还会针对完整的上分位数压力场景求解联合目标；
5. 时域结束后，使用事后天气、碳强度、遥测或已声明的站点模型结算每个方案；
6. 将可行方案同时与基线和使用真实值的 Oracle 比较；
7. 发布假设、违约、预测指标、运营指标和完整谱系。

滚动模式会重算完整时域，但只提交配置步长；每种策略分别结转任务剩余能量，汇总结算只包含已提交时段。任务一旦在某个决策点被接收，其截止时间必须落在当前完整规划时域内；尚未实现跨该时域的终端结转。滚动 Oracle 使用事后信号，但仍遵守任务的因果到达，因此其累计有符号对比不是全局完美预见下界。

预测目标函数和事后结算之间不得泄漏未来信息。

## 7. 必须比较的方案和指标

参考报告比较：

- ASAP/不移峰基线；
- 仅削峰；
- 仅低价；
- 仅低碳；
- 预测感知联合目标；
- 配置精确分位数场景时的上分位数联合目标；
- 使用真实值的 Oracle。

必须输出：

- 站点、IT 和冷却能耗（`kWh`）；
- 运营碳排（`kgCO2e`）；
- 场景电费及币种；
- 站点峰值（`kW`）和可选需量费用；
- 转移能量（`kWh`）；
- 完成任务数、截止时间违约和未服务能量；
- 预测误差与明确的区间覆盖状态；点预测没有覆盖率指标，配置上分位数场景时则报告已提交时段的边际覆盖率、Wilson 不确定性、超越量和 pinball loss，但不宣称双侧或联合覆盖；
- 相对基线的事后真实改善；
- 相对 Oracle 的后悔值。

负收益同样是合法结果。任务转移导致成本、碳排或峰值上升的运行不得被报告隐藏。

## 8. 公开参考案例

第一个公开案例采用可复现的英国单站点回放：

- Open-Meteo [Previous Runs](https://open-meteo.com/en/docs/previous-runs-api) 的历史预报版本，以及 [Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api) 的事后天气；
- 英国官方 [NESO Carbon Intensity API](https://api.carbonintensity.org.uk/) 的碳强度预测和事后估算；
- 仓库内确定性批任务样例，可替换为用户 CSV；
- 明确声明的场景费率，可替换为用户 CSV；
- CI 使用小型离线 fixture，另提供可选的联网刷新命令。

来源清单必须保存来源时间、获取时间、哈希、署名和许可证。打包的 24 小时 fixture 可完全离线运行：

```bash
climadc demo carbon-shift --output-dir ./climadc-replay-runs
```

同一批标准输入也支持 `climadc replay path/to/study.yaml`。独立的 `refresh-carbon-shift` 命令可创建联网刷新快照，但不会覆盖已有目录。

## 9. 产物变化

现有八个 Benchmark 产物继续有效。v0.2 回放至少增加：

- `assumptions.yaml`：站点模型、费率、目标权重和单位；
- `grid-signals.parquet`：合法预报和事后结算信号；
- `workload.parquet`：标准化批任务；
- `schedules.parquet`：基线和候选方案分配；
- `replay-metrics.json`：预测与事后结果；
- `report.html`：可读对比和限制说明。

HTML 报告中的每个派生数字都必须能从这些产物重建。

## 10. 交付阶段

### 阶段 0：语义骨架

- 新增 `GridSignalFrame` 和 `FlexibleWorkloadFrame`；
- 校验因果时间、信号类型、有限数值和物理单位；
- 新增本地 CSV/Parquet 读取器；
- 保持 v0.1 API 和测试兼容。

### 阶段 1：回放内核

- 已实现可替换的站点能耗协议和有界温度敏感 PUE 模型；
- 已用线性容量、释放、截止、功率和能量约束实现 ASAP、仅削峰、仅电价、仅碳排、联合目标和 Oracle；
- 已通过 `ReplayConfig` 和归一化电价信号支持需量费用假设；
- 使用事后天气、电价和碳信号结算调度；
- 输出带单位运营指标、明确不可行原因、相对基线变化和 Oracle 后悔值。

### 阶段 2：参考案例

- 已接入 NESO 和历史 Open-Meteo，并保存不可变来源清单；
- 已增加英国离线 fixture 和拒绝覆盖的可选刷新命令；
- 已实现原子回放产物和自包含对比 HTML 报告；
- 已增加离线集成测试和定时供应方契约检查。

### 阶段 3：可选只读集成

- 已实现 Prometheus range matrix 转换和文档化的 Kepler watts gauge 查询；
- 已实现 Carbon Aware SDK 兼容的当前预测、事后数据和离线 payload 转换；
- 已实现不依赖 SustainDC 运行时的评估 CSV 遥测与碳信号转换。

### 阶段 4：滚动与声明风险场景

- 已实现带决策次数和提交步长校验的滚动时域编排；
- 每个决策点重算完整时域，按策略结转任务剩余能量，并只结算已提交时段；
- 已实现使用精确温度、电价、碳强度上分位数输入的可选联合策略；输入不完整时明确失败，不静默退回点预测；
- 通过既有 CLI 和版本化产物契约发布滚动模式、逐决策求解记录、决策来源和剩余能量状态。

### 阶段 5：事后风险验证

- 只针对已结算的单窗口时段或实际提交的滚动时段，用事后值分别回测每个声明的上分位数；
- 对温度、电价和碳强度发布包含等号的经验覆盖率、有符号覆盖差、95% Wilson 区间、超越幅度和 pinball loss；
- 在 `replay-metrics.json` 和自包含 HTML 报告中暴露完全一致的诊断；
- 保持声明边界：诊断不会重新校准决策，也不能证明联合覆盖、CVaR 或生产性能。

### 阶段 6：多场景套件编排（历史“稳健性”表述）

- 运行至少两份完整、带哈希的回放研究，不修改其输入或来源；
- 汇总前强制统一时域、间隔、执行模式、滚动结构、风险策略可用性、策略集合和币种；
- 发布每种策略的可行性，以及相对各场景 ASAP 基线的等权平均与最坏费用、碳排和峰值变化；
- 只让全场景可行策略进入三目标 Pareto 前沿，同时保留每个场景完整的版本化证据运行；
- 保持声明边界：等权不是发生概率，有限场景最大值也不是尾部风险保证。

以上阶段均不引入生产控制。

## 11. 验收门槛

以下条件全部满足前，v0.2 不算完成：

1. 全新检出后可用一条有文档的命令运行离线参考回放；
2. 所有方案在声明的数值容差内守恒任务能量；
3. 容量、释放时间、截止时间和最大功率违约必须显式报告，不能静默丢弃；
4. 决策只使用当时发布的预报，声明结算值只用于事后结算；
5. 报告包含 `kWh`、`kgCO2e`、峰值 `kW`、币种电费、SLA 和 Oracle 后悔值；
6. 数据来源和许可证署名可机器读取；
7. 离线测试、严格类型检查、Lint、文档构建和包构建全部通过；
8. README 明确区分实测遥测、公开外部数据、仿真值和场景假设；
9. 滚动运行在决策点之间按策略守恒任务能量，并暴露每次已提交决策；
10. 配置的风险分位数必须在三类输入中完整且因果可用；缺失时明确失败，报告不得把该场景描述为 CVaR、经过校准的双侧区间或联合覆盖保证。
11. 启用风险策略的报告只验证已结算或已提交行，显式给出样本数和边际不确定性，并且不得把经验边际覆盖率写成联合保证。
12. 套件报告保留每个场景的输入/配置哈希和完整回放产物；不可行策略必须保留可见，且不能进入 Pareto 前沿。
13. 套件文档和报告必须明确等权、只对可行场景汇总，以及有限声明场景的最坏值边界，不得宣称概率加权稳健性。

## 12. 迁移规则

旧影子调度器继续受支持并输出通用指标，但不得被包装成 v0.2 工程结果。回放内核直接消费新契约，不改变旧 API。删除或转换旧工作负载结构前，必须另行发布带文档的弃用版本。
